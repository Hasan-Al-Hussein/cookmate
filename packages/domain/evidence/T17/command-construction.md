# Command/receipt construction evidence

`commandExecutor.ts` and `favouriteCommands.ts` are internal mobile data modules; no complete provider-level native service factory is exposed yet. This milestone implements registered frozen intent execution and favourites only. Plan/shopping/preferences/conversation mutation handlers remain pending.

App-prepared commands are copied and frozen before async hashing. The executor checks intrinsic/source semantics and fingerprint, then inside the actual serialized transaction reads an existing operation receipt before checking current authority. Same operation/different content conflicts; a valid old receipt remains usable after subsequent context changes. New effects require matching intent revision/phase, stored frozen slot, current conversation/message generation where applicable, and captured relative-date context. Cancelled/reconciling intents cannot run uncommitted slots.

The registered handler applies its state change; collection revisions, receipt and intent phase commit atomically. Notifications occur after confirmed commit or after independent receipt reconciliation proves the attempted commit. Duplicate delivery returns the same receipt. A genuine no-op writes a receipt without pretending the domain state changed. A lost COMMIT acknowledgement returns the actual receipt from a separate reader when available; otherwise the same operation remains uncertain. No fresh operation ID is generated for reconciliation.

Eight desktop SQLite tests cover direct favourite commands, duplicate delivery, new no-op intent, remove/re-add revisions, changed payload, cancelled/stale intent, receipt-insert rollback, commit-ack loss with/without reader, stale chat/day context, executed receipt/state close-and-reopen, and partial-batch cancellation retaining the committed slot. Native storage behavior, complete confirmation/guard capture, live assistant/provider integration and final command acceptance remain unverified. Conversation clear semantics are not claimed from these fixtures.

The independent command review reproduced a missed notification after commit-ack loss plus temporarily unavailable reader. The executor now retains the unannounced change by operation ID until matching durable receipt proof, consumes it before notifying, and drops it if the reader proves no receipt exists. The uncertainty test now checks two concurrent exact retries return the same receipt, notify exactly once and preserve entity revision1. Independent repair recheck closed T17-IR-01; see independent-review.md. This closure covers exact retries within one executor lifetime, not future adapter integration or native acceptance.
