# Conversation persistence construction

28 September 2026. Desktop construction evidence; no native iPhone acceptance.

Brain approved an unreleased genesis schema correction: reference_set now has a per-message ordinal/unique order and assistant_intent_context has an explicit schema version, lifecycle, context revision and bounded request/response/guard/slot-result JSON columns. No user database migration is claimed: no complete production factory/native install has opened this schema. Existing version-one stores are checked against the actual bundled table/index DDL before use; missing/old columns, missing tables or changed constraints fail incompatibility. Existing state is never reset/reseeded. Disposable fixtures are independently created.

The transcript repository pages in ascending display sequence, preserves exact recipe order within each ordered reference set, supports explicit old reference lookup beyond the current page, and isolates current conversation generation. Malformed messages/reference positions fail visibly. Results are immutable snapshots.

The turn repository atomically stores the sending user message, request and awaiting-response intent before network use. It validates request/response catalogue semantics and current conversation, connection, preference and date authority. Successful acceptance binds reference sets to the app-owned displayed assistant message, completes message state, stores the reply and post-response guard baseline, and advances semantic context in one transaction. Draft typing is persisted without advancing semantic conversation context. Response persistence never runs a domain command or creates a receipt.

Persisted metadata is bounded before parsing and revalidated against shared contracts, actual source IDs, intent/origin/revision consistency, guard metadata, slot identity and actual durable receipts. Response errors and interrupted turns remain distinguishable. Source request/history consistency checks and complete context assembly will be integrated with the remaining port methods before exposing a service factory.

Startup recovery must run before factory exposure: unfinished draft/awaiting/clarification/confirmation/ready intents become cancelled; dispatched/reconciling work stays reconciling. Sending messages become interrupted. Receipts remain intact and recovery is idempotent. This prevents an in-memory connection generation that repeats after restart from granting old uncommitted work authority. Malformed nested metadata aborts recovery atomically and is retained for visible storage failure.

Eleven focused SQLite tests cover transcript/reference pagination, durable begin/accept and post-response guards, typing during a wait, message-ID normalization, exact acceptance retry, no mutation/receipt side effects, second-turn rejection, changed-connection rejection, transport failure persistence, response-reference write rollback and exact retry, recovery cancellation, malformed metadata and receipt retention. They also cover lost-ack reconciliation for begin/accept/failure/draft, rejection of contradictory lifecycle/phase metadata, a negative control where an unrelated revision cannot prove a rolled-back write, and day/connection changes during awaited persistence. Two schema tests cover incompatible layouts without reset and bounded schema lifecycle/FKs/receipt independence.

Independent review identified three medium construction findings, all repaired and independently rechecked closed: T25-IR-01 recovered-write notification loss, T25-IR-02 contradictory failed/awaiting metadata, T25-IR-03 stale runtime authority during response writes. The repaired code retains specific durable entity proofs only after transaction settlement, emits once after actual read proof, enforces a lifecycle/phase/response matrix and rechecks runtime authority at callback completion. Recheck: 13/13 targeted tests plus four additional independent probes. See independent-review.md. Native behavior and future adapter integration remain outside that closure.

Full AssistantPersistencePort composition is not callable yet. readContext/current action state, request-context provenance checks, freeze/execute-slot/cancel methods, clear command and complete native factory remain construction work. Native restart, resource release, iPhone performance and end-to-end assistant behavior are unverified.
